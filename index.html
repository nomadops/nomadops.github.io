Our agents

Three agents, each with its own job.

We develop these agents ourselves. They work through MCP servers and pull requests, and they ask before each risky step.

fixer

HeyPenny

General-purpose fixer agent

HeyPenny fixes what breaks. It prepares the fix, and a person approves it.

  • Fixes failed CI runs
  • Prepares rollbacks of bad deploys
  • Runs routine operations from your runbooks
debugger

InspectorGadget

Finder and debugging agent

InspectorGadget finds the cause. It reads logs, metrics and recent changes, and reports what it found.

  • Triages alerts for the on-call engineer
  • Traces errors to the change that caused them
  • Finds drift between your code and your cloud
pipelines

Atlas

Pipeline builder agent

Atlas builds pipelines. It sets up CI/CD for your repositories, with checks on every change.

  • Builds CI/CD pipelines for your repositories
  • Adds Terraform plan and Pulumi preview checks
  • Updates pipelines when your stack changes

MCP servers for your app

Let agents operate your app, within limits you set.

MCP (Model Context Protocol) is the open standard that lets AI agents use tools. We build MCP servers for your app, made for SRE and DevOps work. Agents get the tools they need to check, operate and fix your app, and nothing more.

  • Read tools for health, logs, deploys and queues
  • Action tools with an approval rule for each action
  • A log of every call, by agent and by person
  • Works with any agent that supports MCP

Operations tools in your app

Operations panels, built into your product.

We build useful operations tools and panels directly into your app. Your team sees health at a glance, fixes common problems in one click, and reviews what agents did. Agents get the same actions through your MCP server, with the same rules.

  • Health and status views for each part of your app
  • Admin actions with confirmation and an audit log
  • Agent activity and approvals in one place

How we keep agents safe

Agents propose. People approve.

Every agent we build or connect uses the same review path as your engineers. Nothing changes in production until a person says yes.

  1. Agent
  2. Proposed change
  3. Policy checks
  4. Human review
  5. Apply

Only the access it needs

Each agent gets its own identity and only the tools and permissions its job needs.

Risky actions wait for a person

Infrastructure changes go through pull requests. App actions through MCP wait for approval.

Agent setup lives in Git

Tools, prompts and permissions are code, reviewed and versioned with your infrastructure.

Every action is logged

You can see what each agent did, when it did it, and why.
